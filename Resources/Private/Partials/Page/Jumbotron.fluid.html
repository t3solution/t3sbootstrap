w-100 is mandatory here, not cosmetic. .jumbotron is a flex container, so this div is a flex item without a width of its own - it shrinks to its content. Below it hangs jumbotron-content.w-100, whose 100 % refers to a width that does not exist yet at that point. If a background wrapper with a local video sits in there, its figure is absolutely positioned by Bootstrap's .ratio and contributes nothing to the width either - the whole chain computes down to 0 and the video disappears. This only shows in a jumbotron without a container: there this div is the only one that could set a width. The second variant further up in this partial already does it this way.
If the jumbotron has a container, the page title's stays out - two inside each other would be double padding and a second width limit. If it has none, the page title's container applies. This very branch is reached without a container (see the condition of this section): without the check the title would run edge to edge while everything else in the jumbotron sits indented.
Only skip it where the jumbotron itself has a container.
The video case comes before the image case: bgSlides is empty then, because the video replaces the image stack - so the condition below would no longer apply. The ratio class sits in config.jumbotron.class and counts for both; Bootstrap's .ratio makes every direct child fill the format, the video included.
