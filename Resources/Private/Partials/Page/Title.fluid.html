The container around the page title, chosen under "Container" in the configuration. It takes effect everywhere the title would otherwise run edge to edge across the page. If the surrounding section already brings a container, a second one inside it would be double padding and a second width limit - those places set pageTitleSkipContainer. What counts is whether the section ACTUALLY has a container, not which section it is: a jumbotron on a page without a container has none, and then the title's container does belong. {config.general.pageTitlecontainer}

The navigation title instead of the page title, when the configuration record asks for it. An empty nav_title falls back to the title - an option must not be able to produce an empty h1. {data.nav_title -> f:format.raw()} {data.title -> f:format.raw()}

The page field "Subtitle", off by default. A paragraph and not a heading: a heading would announce a section that does not exist, it would take the h2 level away from the first real content section below, and it would show up as its own stop in the heading navigation of a screen reader. hgroup is exactly this case in the HTML standard - one heading plus any number of paragraphs. The element itself has no ARIA mapping and is not announced; the gain is in the p. mb-2 because Reboot gives a p a bottom margin of 1rem and a heading .5rem - without it the gap below the title would grow. Up to 5.3.57 this was an h2 and was printed whenever the field was filled. Project styles addressing .page-title h2 have to follow; page-subtitle is there as a stable target, the markup offered none before.
